# Collaborative Workspace 1.0 architecture

The isolated `cortex-collaborative-workspace` runtime turns one explicit absolute human workspace into a Core-validated outer Collaborative Workspace plus nested Agent Workbench. The stable outer manifest contains only the contract, one UUIDv4 workspace identity, and fixed role paths. The dynamic manifest lives at `agent-workbench/ref/.agent-workbench.json` and records canonical source identities, generation, source-to-KU mappings, provider routes, prepared KU digests, quality, and warning codes; neither manifest stores absolute paths, timestamps, or task prompts.

`prepare` is the only writer. A missing root is fully built and validated in a same-volume sibling stage before publication. A safe ordinary directory is adopted without changing its raw `ref/` or extras; fixed artifacts are installed exclusively and the stable manifest is written last. Recognized workspaces use two source scans for exact no-op or drift rejection. Stale refresh requires literal-empty `temp/`, rechecks root/ref/temp identities and source records, then replaces only prepared `ref/`, retaining the old directory only long enough to restore an ordinary rename failure. The runtime has no persistent transaction or crash-recovery state.

Source records are NFC relative POSIX paths sorted by path. Ordinary-file digests are SHA-256 of source bytes; valid Knowledge Units use Core's canonical tree digest. Projection preserves the complete basename (`a/report.docx` becomes `a/report.docx/`). PDF and supported Microsoft Office formats route only to file-conversion; the remaining fixed supported set routes only to markdown-conversion. Providers receive task-owned snapshots and `--bundle-name-mode source-basename`, never raw-ref paths. Unsupported, unsafe, colliding, drifting, failed, or invalid inputs block publication; valid partial/warning KUs publish as `ready_with_warnings`.

`status` and `validate` are read-only. Recognized structural tampering is `invalid` and is never re-adopted or repaired. The public surface intentionally excludes delete, clean, force/rebuild, watchers, queues, schedulers, dynamic provider discovery, journals, receipts, crash recovery, permission normalization, KB/Notes ingestion, output promotion, and task lifecycle management.
