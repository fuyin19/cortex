# Collaborative Workspace 1.1 architecture

The isolated private Collaborative Workspace adapter turns one explicit absolute human workspace into a Core-validated outer Collaborative Workspace plus nested Agent Workbench. The stable outer manifest contains only the contract, one UUIDv4 workspace identity, and fixed role paths. The dynamic manifest lives at `agent-workbench/ref/.agent-workbench.json` and records canonical source identities, generation, source-to-KU mappings, provider routes, prepared KU digests, quality, and warning codes; neither manifest stores absolute paths, timestamps, or task prompts.

`prepare` is the only writer. A missing root is fully built and validated in a same-volume sibling stage before publication. A safe ordinary directory is adopted without changing its active raw references or extras; the fixed `ref/_outdated/` role is added if absent, fixed artifacts are installed exclusively, and the stable manifest is written last. Recognized workspaces use two source scans for exact no-op or drift rejection. Stale refresh requires literal-empty `temp/`, rechecks root/ref/temp identities and source records, then replaces only prepared `ref/`, retaining the old directory only long enough to restore an ordinary rename failure. The runtime has no persistent transaction or crash-recovery state.

Both reference roles contain `_outdated/`. The outer directory is human-owned, safely structured, and excluded from active source scans. The inner directory is runtime-owned and contains one strict `generation-<old-generation>-<UTC-minute>/` batch for each refresh that retires sources; each leaf is the previously validated KU at its original source path. A source retires automatically when it disappears or its kind/digest changes. Repeatable `prepare --outdate <relative-path>` explicitly retires unchanged active sources, moving their outer raw items and archived KUs into the same batch. A no-op reads no clock and changes no bytes.

Source records are NFC relative POSIX paths sorted by path. Ordinary-file digests are SHA-256 of source bytes; valid Knowledge Units use Core's canonical tree digest. Projection preserves the complete basename (`a/report.docx` becomes `a/report.docx/`). PDF and supported Microsoft Office formats route only to file-conversion; the remaining fixed supported set routes only to markdown-conversion. Providers receive task-owned snapshots and `--bundle-name-mode source-basename`, never raw-ref paths. Unsupported, unsafe, colliding, drifting, failed, or invalid inputs block publication; valid partial/warning KUs publish as `ready_with_warnings`.

`status` and `validate` are read-only. Recognized structural tampering is `invalid` and is never re-adopted or repaired. Retirement does not add a sync command, fuzzy duplicate detection, automatic outer-file movement, rollback generations, or archive cleanup. The public surface intentionally excludes delete, clean, force/rebuild, watchers, queues, schedulers, dynamic provider discovery, journals, receipts, crash recovery, permission normalization, KB/Notes ingestion, output promotion, and task lifecycle management.

Collaborative Workspace 1.1.3 uses the installed launcher's exact sibling `anti-entropy-core` skill by default, with a present `ANTI_ENTROPY_CORE_RUNNER` override taking priority and invalid values failing without fallback. It validates ordinary non-reparse path components, then preflights exact Core 1.2.1 and ABI `anti-entropy-core.runner/v1` within 30 seconds before acquiring a writer lock or staging. One operation retains the selected path for every Core request and explicitly passes it to each converter subprocess. Each routed provider still requires its explicit absolute runner. Its matching config variable is optional when absent, omitting `--config`; when present, including empty, existing strict absolute ordinary non-link/reparse leaf and full ancestor-chain checks apply before the provider can run. Conversion providers require the matching installed `file-processing` support skill; Cortex does not carry that runtime.
