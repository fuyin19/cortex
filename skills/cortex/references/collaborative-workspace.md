
# Cortex Collaborative Workspace

Use this role only when the user explicitly invokes `cortex` and the router selects the Collaborative Workspace domain. Generic workspace, file-processing, KB, note, or coding requests are insufficient triggers.

Own exactly `collaborative_workspace.prepare`, `collaborative_workspace.status`, and `collaborative_workspace.validate`. Use the platform launcher, which deterministically selects an already-installed Python 3.11/UCD 14 interpreter, preferring `CORTEX_PYTHON`. It never installs, downloads, or recursively searches for Python. Use one explicit lexical absolute `--root`:

```text
Windows: <ABSOLUTE-CORTEX-SKILL>/scripts/collaborative-workspace/run_collaborative_workspace.ps1 --json prepare --root <absolute-collaborative-workspace>
POSIX: <ABSOLUTE-CORTEX-SKILL>/scripts/collaborative-workspace/run_collaborative_workspace.sh --json prepare --root <absolute-collaborative-workspace>
Add --outdate <relative-source-path> once per explicitly retired source. Replace prepare with status or validate for read-only operations.
```

The installed launcher binds the sibling `anti-entropy-core` skill at `<cortex-skill-parent>/anti-entropy-core/scripts/knowledge_unit_runner.py`. An explicit `ANTI_ENTROPY_CORE_RUNNER` absolute path overrides that default; a present empty, relative, missing, linked/reparse, or nonregular value fails without fallback. Core-dependent operations preflight ABI `anti-entropy-core.runner/v1` and exact Core version `1.2.1` within 30 seconds before business writes, then retain that runner for the operation. Every converter subprocess receives this same selected runner explicitly. File and Markdown conversion default to their fixed sibling pipelines; present `FILE_CONVERSION_RUNNER` or `MARKDOWN_CONVERSION_RUNNER` values override those defaults strictly. Matching config variables remain optional when absent and strict when present. After source scanning and the exact no-op decision, prepare checks each used route once for only the suffixes present. A Python-local missing `pypdf` or AnyDoc capability may select the next eligible interpreter before any stage exists; installation, config, host-tool, and protocol failures never fall back. There is no package installation, network access, provider registry, cache, or additional source scan.

`prepare` is the only writer. It creates a missing root, adopts a safe ordinary directory, returns an exact no-op for unchanged source records, or refreshes only `agent-workbench/ref/`. Both reference roles have `_outdated/`: outer history is human-owned and excluded from active projection; inner history is strict, generation-batched, and system-owned. Missing or changed active sources retire their old prepared KUs automatically. Use `--outdate` only for an exact unchanged active source the user explicitly asked to retire; this is the sole operation that moves raw outer references. Prepare never clears or modifies `agent-workbench/temp/` or `agent-workbench/output/`. A stale workspace with nonempty `temp/` returns `busy`; do not delete or move those files automatically. Report all returned blockers and warning codes. A nonzero provider exit keeps its route and exit code; when stderr is nonempty, each failed source issue also carries the sanitized rightmost 4096 characters in `provider_stderr_excerpt` and the `provider_stderr_truncated` flag. Do not infer duplicate retirement, and do not add sync, delete, clean, force, rebuild, watch, queue, journal, recovery, KB/Notes ingestion, output promotion, or task-lifecycle behavior.
