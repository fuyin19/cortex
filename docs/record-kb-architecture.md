# Record Bundle architecture

Layout 4 adds one physical tag dimension: `profiles/`, then an exact selected Tag 2 value, then unchanged Layout 3-shaped record units. Partitions are direct, real, nonempty directories. Full units require the Markdown/JSON pair and sole `src` file to share one stem (extensions may differ). Exact case-folded `.cortex`, `.cortex-*`, nested partitions, registries, indexes, manifests, hidden state, and legacy wrappers are invalid at every payload depth.

Add derives its partition from metadata. Existing and newly created partitions use bounded sibling staging and no-replace publication. Edit/show/delete authorize the exact `--partition` plus `--record` pair. V2 tree hashing prefixes the UTF-8 partition and unit lengths/bytes before the sorted no-follow manifest. Delete removes the authorized unit leaf-first and removes its now-empty partition; partial failure is reported without recovery artifacts.

Skill ownership is deliberately outside the core route surface. `cortex-kb-ingest` owns add and exact-v1 batch, `cortex-kb-build` owns initialization/configuration/registration, and `cortex-kb-manage` owns reads/validation and exact record show/edit/delete. Every embedded runtime remains complete. The ingest helper accepts only a complete exact v1 job, validates it before any runner call, and invokes the unchanged `record.add` route sequentially through the bound interpreter. It collects valid non-ok Results without rollback and creates no persistent state. Only ingest and its deprecated `cortex-build` compatibility alias carry the helper.

Build is a skill-level ordered transaction protocol without rollback or extra durable state. It binds one explicit target; validates complete candidate Tags, Layout, and Registry objects against keyed-monotonic retention; and rejects contraction before writing. Populated Bundles freeze profile bytes. Empty configured Bundles retain their group/strategies and may preserve/increase the maximum, writing Layout before Tags only for a maximum increase. Empty null-sentinel Bundles always write Tags before selecting an existing candidate group in Layout. Registry is last. The first failure stops later steps and reports the exact residual/orphan state together with the core Result.

The repository migration utility guards every required profile read and returns a deterministic invalid-plan body aggregating missing, malformed, linked, nonregular, unreadable, record, payload, and naming defects. A clean plan requires exact canonical Record 1/Tag 2/Layout 3 JSON and every flat unit's derived Layout 3 name. Build independently validates the source's canonical Registry 1 direct-child relation, zero-byte root lock, every other registered physical target as Layout 4, absence of orphan complete Bundles, and the derived KB repository; ordinary unrelated entries remain ignored and the actual Cortex repository is always protected. Candidate/stage containment and same-volume checks occur before output, and omitted or false boundaries fail closed. There is no product migration or cutover route.
