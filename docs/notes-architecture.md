# Cortex Notes 2.0

Cortex Notes is a portable file-native capture layer parallel to the record KB. One explicit absolute root contains exact Registry 1, a stable `.notes.lock`, and the three registered Bundles. Each Bundle contains exactly `profiles/note-schema.json`, `profiles/tags.json`, and `profiles/layout.json`, plus its direct partition directories. A legacy `bundle.json` is invalid; there is no fallback, compatibility mode, or migration route.

Note Profile 1 is one fixed canonical object and is byte-identical in every Bundle. It declares, in order, required `version/integer`, `id/string`, `title/string`, `created_at/string`, `bundle_id/string`, `partition/string`, `tags/string-list`, and `body/string` fields. A note unit remains exactly canonical `note.json` plus UTF-8 `note.md`; active units are direct partition children and archived units are under the exact `archive/` directory.

Tag Profile 2 is validated by the Notes runtime without importing Cortex KB. Daily notes use no groups. Tool feedback uses one `tool` group, initially containing the five repository tags. Ideas uses one `idea` group with `new-tools-and-functions` and `preliminary-concepts-and-proofs`. Layout Profile 1 is a closed non-executable policy: exact Hong Kong `YYYYMMDD` date partitioning, or one tag group with `keyed-monotonic` expansion and either `safe-component` or `git-repository-under-tools-root` admission. All behavior after initialization dispatches from these validated profiles, never from a Bundle id.

Only a complete Tag 2 candidate may change. Existing group and tag keys, order, and membership cannot contract, rename, move, or collide; descriptions may change and one or more safe tags may append. Under the stable root lock, the runtime reloads authoritative profiles, validates the whole candidate and every required Git repository, publishes missing canonical partition/archive skeletons in candidate order, and atomically replaces `profiles/tags.json` last. The first failure stops later work without rollback and reports `completed_steps`, `failed_step`, `residual_partitions`, and `profile_updated`. Only canonical empty unregistered skeletons named by a valid retry candidate are resumable; normal selected-Bundle operations report them as residue.

Daily add derives one `+08:00` timestamp once, accepts an omitted or identical partition, creates a missing date/archive skeleton under the same lock, and atomically publishes the note. An explicit tools root is required only for tools-Bundle initialization, adding tools tags, or adding a note to a Git-admission partition. Reads, validation, and existing-note management never require a live tools root, so stale configured tools partitions remain read/manage-only.

Every component and containment check is no-follow. Absolute/drive/UNC-like components, traversal, separators, controls, Windows reserved names, trailing dot/space, NFKC changes, case-fold collisions, reserved Notes names, runtime temporary prefixes, links, junctions, reparse points, and wrong node types reject. A tools repository is an exact-case same-name ordinary direct child of the explicit absolute tools root with an ordinary `.git` directory. Atomic temporary entries stay beside their destination.

Edit changes Markdown only, archive is a one-way same-partition move, and confirmed delete is irreversible. Existing-note mutations require a fresh digest binding root identity, selectors, archive state, metadata, and body. The runtime scans the filesystem directly and has no database, index, search, vector store, UI, server, listener, network client, synchronization, backup, cross-partition move, restore, trash, or tombstone.
